> **Scope — read this before copying anything out of here.** Cursor's Agent CLI
> reads a project-root `CLAUDE.md` and applies it as rules *alongside*

> contract. It does not restate the operating rules the claude render already
> injects — those live in the framework files it points at.

## Capabilities

The agentic OS ships its own capabilities as Cursor skills under
`@@CURSOR_CONFIG_DIR@@/skills/`. Their descriptions are presented to the agent,
which may apply one when it is relevant; invoke one explicitly by typing
`/<name>` in Agent chat (e.g. `/session-agent`). Cursor reads a capability's
`SKILL.md` body when the skill is used.

**`/session-agent` is the spine.** The framework `sessionStart` hook directs you
to invoke `/session-agent` as the first action of every session — Mode 1
(kickoff orient: memory + active work + vault + reconciliation) then route the
user's first prompt. On every subsequent non-trivial prompt, re-invoke
`/session-agent` (Mode 2: route only — orient is already live in context). One
capability, two modes; the body teaches both. A `preToolUse` hook matching the
file-modifying tools enforces the gate before file edits as a safety net: open
it by writing the routing declaration to
`@@CURSOR_CONFIG_DIR@@/agentic-os/gate-<conversation_id>` as the capability's
realization instructs.

## Pre-Push

Before opening a PR or pushing a branch with framework changes, run
`make verify` from the repo root. It runs the verification gates in order,
failing fast on first non-zero exit: the acceptance suite, static validation,
and the manifest-based drift check across every rendered harness home
(`scripts/check-drift.sh --auto`; a home that is unset or not yet rendered is
skipped with a notice). These are the same gates a future session or a
future-operator runs when picking up the change.

Commit identity: a clone with no repo-local git identity derives the operator's
personal name and machine hostname into public history on a plain commit. Pin
every framework commit to your published identity (`git -c user.name=… -c
user.email=…`, or a repo-local `git config`).

## Cursor-specific mechanics

These are harness mechanics, not framework rules — they exist because of how
Cursor loads configuration, and they are documented in full in
`@@AI_CONFIG_DIR@@/harnesses/cursor/adapter.md`.

- **Where this file is read from.** Cursor discovers `AGENTS.md` from a project
  root and its nested subdirectories. Whether a user-level copy at
  `@@CURSOR_CONFIG_DIR@@/AGENTS.md` is auto-loaded is an open question recorded
  as U2 in the adapter's UNVERIFIED block — if the agent never seems to have read
  this file, add a thin project-root `AGENTS.md` pointing at
  `@@AI_CONFIG_DIR@@/` and this file stays the canonical text it points at.
- **The generated config is build output.** `@@CURSOR_CONFIG_DIR@@/hooks.json`,
  `@@CURSOR_CONFIG_DIR@@/skills/` (the spine subdirs), and this file are
  regenerated by `install.sh`. Hand-edits are reported by the drift gate.
  `cli-config.json`, `permissions.json`, `sandbox.json`, `mcp.json`,
  `commands/`, `agents/`, and `rules/` are yours — the build never writes them.
- **Cloud Agents do not run this harness's hooks.** User-level hooks and
  `sessionStart` never fire there; only project-level `.cursor/hooks.json`
  (committed into the target repository) does. In a Cloud Agent the spine
  contract is instruction-only — follow it anyway; nothing will block a
  violation.
- **Commit attribution.** Cursor's `attribution.attributeCommitsToAgent`
  defaults on, adding a "Made with Cursor" commit trailer. Turn it off where
  commits are identity-pinned.
