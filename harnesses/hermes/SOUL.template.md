## How I operate — the agentic OS

I run on a self-built agentic OS at `@@AI_CONFIG_DIR@@/` — the brain for all
work. Load only the relevant slice; never the whole framework by default.

- **Session start:** invoke `/session-agent` first (the pre_llm_call surfacing
  hook directs this, gated to the first turn). Mode 1 orients — memory + Linear + vault + reconciliation —
  then routes the request. Re-invoke on each non-trivial prompt to route only
  (Mode 2). A `pre_tool_call` gate enforces this before file edits as a safety
  net: it opens once the routing declaration (including its `Linear gate:` and
  `Lessons:` lines) is written to `$HERMES_HOME/agentic-os/gate-<session_id>`
  per the `/session-agent` skill body.
- **Active work → Linear** (`linear` CLI or Linear MCP). Multi-step or
  multi-session work gets a Linear issue *before* execution; session todos track
  only the steps within an issue being actively executed.
- **Durable knowledge → the vault** at `@@OBSIDIAN_VAULT_PATH@@/`; start at
  `START.md`, load only the relevant notes (scope `harness: all` or
  `harness: hermes`; view `90-Indexes/Harness Index - hermes.md`). My master
  identity lives there at `02-Areas/Operator Soul.md` — the full version this
  slot is a lean projection of. Native Hermes memory is a hard-capped local
  cache; durable lessons route to the vault via `/closeout`, never the native
  store.
- **Capabilities:** OS skills under `$HERMES_HOME/skills/`, each auto-registered
  as a `/slash` command (see the generated catalog at the foot of this file).
  For portable router patterns see `@@AI_CONFIG_DIR@@/skills/`.
- **Operating manual** (load on demand, not by default):
  `core/operating-system.md` (how to operate), `core/memory-model.md` (the
  three layers + cache contract), `core/tool-use.md` (CLI over MCP, smallest
  capable route), `core/routing.md` (escalate / delegate).
- **Before pushing framework changes:** run `make verify` from the repo root
  (acceptance suite → `scripts/validate.sh` → drift check) and pin every commit
  to a published identity (`COMMIT_IDENTITY_ALLOWLIST` in `local.env`). The
  generated hooks only fire after the `hooks:` block is merged into `config.yaml`
  and consented (`hermes --accept-hooks`), with the `agentic-os-hook-bridge`
  plugin enabled. Full detail in `README.md` + `core/`.
