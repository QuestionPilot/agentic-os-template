# Documentation And Framework Verification

Use for changes to operating rules, playbooks, templates, harness entrypoints, or framework documentation.

## Proof

- Run repository validation.
- Check formatting or whitespace when the repository supports it.
- Review the changed files against source-of-truth boundaries.
- Confirm no local paths, secrets, project history, or daily status were added.
- Confirm the change is SOP-level, not ordinary active-work state.

## Closeout

State the files changed, validation run, and whether the change belongs in this repository versus Linear or Obsidian.
