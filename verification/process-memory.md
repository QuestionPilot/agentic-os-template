# Process And Memory Verification

Use for changes to operating process, memory boundaries, retrieval, or closeout standards.

## Proof

- Confirm the right source of truth changed.
- Confirm active work belongs in Linear, durable knowledge belongs in Obsidian, and SOP changes belong in this repository.
- Check that the change improves future behavior rather than preserving ordinary chatter.
- Check whether recurring work needs `playbooks/goal-run.md`.
- Check whether raw-data-heavy work needs `playbooks/data-readiness-map.md`.
- Run repository validation.
- Confirm no raw transcripts, local paths, secrets, or project history were added.

## Closeout

State the behavior changed, where future agents should retrieve it, and whether any Linear or Obsidian follow-up is needed.
